# 프롬프트 작업 기록

AI(Claude Code)와 협업하며 내린 주요 의사결정을 기록한다.

## 2026-11-05

### 1. 심사 기준 정리
- 심사 기준, 필수 조건, 제출물을 `CLAUDE.md`에 정리해서 AI가 매 작업마다 기준을 참고하도록 함

### 2. 아이디어 결정
- 처음 구상: 인디밴드 팬 커뮤니티
- AI 피드백: 사용자가 없으면 데모 때 비어 보이고, AI가 핵심 기능이 아님 → 커뮤니티는 확장 계획으로 넘김
- 최종: **플레이리스트 캡처 / 텍스트 입력 → AI 취향 분석 → 인디밴드 추천** (주제 2. 맞춤형 추천)

### 3. 문제 정의
- 직접 겪은 불편함: 인디밴드는 좋아하는 사람이 적어서 추천받기 힘듦
- 원인 분석: 기존 음원 플랫폼 추천은 청취자 수 기반이라 듣는 사람이 적은 밴드는 노출이 안 됨
- 차별점: 인기가 아니라 음악의 결(사운드, 분위기, 가사)로 추천 + 추천 이유 설명 + 어떤 음원 앱이든 사용 가능

### 4. 리스크 대응
- AI가 없는 밴드를 지어낼 수 있음(환각) → 실제 인디밴드 데이터 목록 안에서만 추천하도록 설계
- 캡처 인식 오류 가능 → 읽은 곡 목록을 사용자가 확인·수정하는 단계 추가

### 5. 기술 스택
- Streamlit vs HTML + Vercel 비교 → 디자인 자유도와 발표 인상을 고려해 **HTML + Vercel** 선택
- 브라우저에 API 키를 넣으면 누구나 볼 수 있으므로 Vercel 서버 함수에서만 AI를 호출하도록 설계

### 6. 화면 모양 제작
- AI 연결 전, 샘플 데이터로 전체 흐름(입력 → 곡 확인 → 로딩 → 결과)을 먼저 구현
- 서비스 이름(가칭): **결 GYEOL**, 슬로건 "인기 순이 아니라 음악의 결로."

### 7. 밴드와 노래 연결
- 결과 카드에 밴드마다 추천 노래 여러 곡을 연결하고, 첫 곡은 "이 노래부터 들어보세요"로 강조
- 곡마다 ▶ 버튼으로 바로 들어볼 수 있게 함. AI가 영상 주소를 지어내지 않도록 "밴드명 + 곡명" 유튜브 검색으로 연결
- `data/bands.json`에 밴드 → 노래 구조의 데이터 틀을 만듦 (AI는 이 목록 안에서만 추천)

### 8. 아티스트 데이터 채우기 (1차: 4팀)
- 한로로, 극동아시아타이거즈, 고고학, 우효를 `data/bands.json`에 추가
- AI가 기억만으로 쓰면 곡명을 지어낼 수 있어서, 웹 자료(위키백과, 벅스, 소속사 페이지 등)로 확인한 곡만 넣고 출처를 함께 기록
- 분위기(mood) 설명은 자료를 바탕으로 정리한 것이라 팬이 직접 확인하도록 `checked` 표시를 둠
- 솔로 아티스트(한로로, 우효)도 포함되어 `type` 항목(밴드/솔로) 추가

### 9. 아티스트 데이터 확장 (17팀) + 임시 추천
- 신인류, 정우, 청요일, 숨비, 다브다, 코토바, 녹이녹, 카디, 유인원, 김뜻돌, 심아일랜드, 음성녹음, 언니네 이발관 추가
- 범위를 "인디밴드"에서 "인디 아티스트(밴드 + 솔로)"로 넓힘
- 13팀을 세 묶음으로 나눠 동시에 웹 조사. 동명이인(정우-배우)이나 일반 단어(유인원, 음성녹음)와 겹치는지 확인
- AI 연결 전 임시로 키워드 매칭 추천을 붙임: 입력에서 데이터 속 아티스트 이름이나 분위기·장르 단어를 찾아 비슷한 아티스트를 보여줌
- 한계: 데이터에 없는 아티스트나 표현은 이해하지 못함 → 생성형 AI가 꼭 필요한 이유 (발표 포인트)

### 10. Gemini AI 연결
- ChatGPT 유료 구독은 API와 별개 상품이라 웹사이트에 연결할 수 없음을 확인 → 무료 사용량이 있는 Gemini API 선택
- "무료 키니까 공유돼도 괜찮다"는 생각을 짚음: 키가 새면 남이 사용량을 다 써서 심사 때 데모가 멈출 수 있으므로 계속 비공개로 관리
- Node.js가 없는 환경이라 서버 함수를 Python으로 작성 (`api/gemini.py`, Vercel Python 함수). 로컬 테스트는 `dev_server.py`
- AI 기능 2가지: ① 캡처 이미지에서 곡 목록 읽기 ② 취향 분석 + 데이터 안에서 추천 + 추천 이유 생성
- 환각 방지: 프롬프트로 "목록 안에서만" 지시 + 서버에서 목록에 없는 아티스트·곡을 한 번 더 걸러냄
- 데모 안정성: AI 호출이 실패하면 임시 키워드 추천으로 자동 대체

### 11. 추천 방식 다양화
- 사진으로 추천받기: ① 좋아하는 아티스트 리스트 캡처 ② 좋아하는 노래 리스트 캡처 (캡처 종류마다 AI가 읽는 방법이 다름)
- 텍스트로 추천받기: 버튼을 누르면 입력 방식이 바뀜
  - 노래의 분위기 (분위기 버튼 여러 개 선택) / 비슷한 밴드 / 비슷한 노래 / 비슷한 느낌(장면·영화·계절) / 자유 설명
- 추천 방식마다 AI에게 다른 지시를 줌 (예: 비슷한 노래 모드는 원곡과 닮은 곡을 첫 번째에, 느낌 모드는 장면을 사운드로 해석)
- 사용자 입력이 프롬프트의 다른 부분을 바꾸지 못하도록 입력을 맨 마지막에 넣음
- 이전 AI 연결 작업에서 생긴 JS 문법 오류(문자열 안 줄바꿈)를 발견해 수정, 헤드리스 브라우저로 화면 동작 자동 테스트

### 12. 데이터 대폭 확장 (56팀) + 아티스트 사진
- 사용자가 고른 43팀 중 새 39팀 추가 (4묶음 동시 웹 조사, 각자 파일로 저장 후 합침)
- 아티스트 사진: Deezer 공개 API에서 "아티스트명 + 곡명"으로 검색해, 곡 제목과 아티스트 이름이 모두 맞을 때만 사용 (동명이인 방지). 못 찾으면 이름 첫 글자로 표시
- 디자인: 어두운 테마 → 베이지 톤, 화면 문구와 AI 출력 길이를 짧게 제한 (사용자 피드백)

### 13. 실제 AI 연결 성공
- API 키를 `.env`에 넣고 테스트. 첫 시도는 Google 쪽 과부하(503)로 실패
- 해결: 내 키로 쓸 수 있는 모델 목록을 확인하고(`scripts/list_models.py`), 바쁘거나 늦으면 예비 모델로 자동 전환 (50초 안에서)
- 결과: "보수동쿨러"처럼 데이터에 없는 아티스트는 "잘 모른다"고 솔직히 말한 뒤 다른 단서로 추천 → 환각 방지 규칙이 동작함

### 14. 속도 개선 · 숨은 곡 · 이름 변경
- 느린 원인 측정: AI의 '생각 시간'이 대부분 → 생각 시간을 꺼서 약 40초 → 5초
- "인기곡만 추천한다" 피드백 → Deezer 앨범 수록곡에서 아티스트별 숨은 곡(최대 10곡)을 수집. 실제 수록곡만 쓰므로 환각 없음. AI는 숨은 곡을 먼저, 대표곡은 최대 1곡만 고름. 화면에 "숨은 곡" 표시
- 서비스 이름: 결 → **B-SIDE** (레코드 뒷면 = 타이틀곡에 가려진 숨은 곡). LP 레코드판 로고 제작, 부제 "인디음악 디깅하기"
- 상단 바에 로고 + 홈 버튼 추가

### 15. 아이콘 개선
- "아이콘이 구리다" 피드백 → 이모지(📷🎸🎵 등)는 기기마다 모양이 달라지고 베이지 톤과 안 어울림
- 같은 선 굵기의 SVG 선 아이콘 10개로 통일. 색은 버튼 상태(기본 회색 / 선택 시 테라코타)를 그대로 따라감

### 16. 데이터 밖 아티스트도 추천 (AI 역할 확대)
- 사용자 피드백: "ddbb를 넣었는데 다브다로 연결했다", "내가 넣은 정보만 찾으면 AI를 연동한 이유가 없다"
- 원인: 환각을 막으려고 추천을 우리 데이터 56팀 안으로만 묶어 둠 → AI가 모르는 밴드는 이름이 비슷한 팀으로 착각
- Google 검색 연동을 시도했지만 무료 키로는 쓸 수 없음(429) → 키 없이 쓰는 공개 음악 DB(Deezer, MusicBrainz) 활용
- 바꾼 점
  1. 입력 속 모르는 아티스트는 Deezer·MusicBrainz에서 실제 정보(국적, 장르, 곡 목록)를 조회해 AI에게 전달
  2. AI가 데이터 밖의 실존 한국 인디 아티스트도 추천 → 서버가 Deezer에서 "아티스트+곡"이 실제로 있는지 검사, 없으면 버림
     (테스트: 세이수미 통과 / 해외 밴드·지어낸 이름 차단). 화면에 "AI 발견" 배지
  3. "더 찾아보기" 버튼: 이미 본 아티스트를 빼고 3팀씩 더 추천
- 환각 방지 방식이 "닫힌 목록"에서 "자유 추천 + 외부 DB 검증"으로 바뀜 → 발표 포인트

### 17. 아티스트 사진 수정
- 라쿠나: 외국 동명이인 사진 → 실제 라쿠나로 교체 / 오월오일: 영문명 괄호 때문에 검색 실패 → 수정
- Deezer는 곡 제목을 영어로 등록한 경우가 많아, 이름이 정확히 같은 아티스트 사진을 쓰는 2차 방법 추가 → 15팀 사진 추가
- Deezer 기본 이미지(빈 사진) 3팀은 이름 첫 글자로 표시

### 18. 실험: 타브 악보 영상에서 코드 읽기
- 아이디어: 기타 타브 악보 영상을 넣으면 코드 진행이 비슷한 노래를 찾기
- 테스트(`scripts/test_tab.py`): Gemini에 유튜브 주소를 그대로 주고 코드를 읽게 함 (오월오일 - Echo)
- 결과: 같은 모델 2번 모두 G - Ddim7 - Em7 - Dm7 - C - D (화면의 코드 이름을 읽었다고 답함)
- 한계: 한 번에 20~67초 (배포 서버 제한 60초에 걸릴 수 있음), 영상이라 무료 사용량을 많이 씀(다른 모델은 사용량 초과),
  곡 앞부분만 읽음, 비교할 다른 곡들의 코드 데이터가 없음

### 19. 노래 제목을 원래 한국어로 / 화면 아이콘 정리
- 피드백: "노래 제목이 영어로 뜬다, 유튜브 뮤직 이름으로" → Deezer가 한국 곡 제목을 영어로 번역해 둔 경우가 있었음 (예: "__에게" → "To. __")
- 애플뮤직 검색(무료)은 결과가 자주 비어서 탈락. 곡 고유번호(ISRC)로 MusicBrainz(원어 제목 사용)를 조회하는 방식 선택 → 이름이 아니라 번호로 찾아서 다른 곡과 안 헷갈림
- 숨은 곡 12곡을 한국어 제목으로 교체 (`scripts/fix_titles_korean.py`), 대표곡과 겹친 2곡 제거. "AI 발견" 아티스트 곡도 서버에서 같은 방식으로 변환
- 피드백: "아이콘이 너무 많아 보인다" → 탭은 글자 + 밑줄, 선택 버튼은 아이콘 없는 작은 알약 모양으로. 업로드 아이콘 하나만 남김

### 20. 공개 전 보안 점검 (업로드·배포 전)
- 사용자 요청: "기능보다 보안 우선, 승인 전에는 업로드·배포 금지, 비밀값은 채팅에도 출력 금지"
- 점검: .gitignore/.vercelignore, 전체 파일 비밀값 패턴 검사, .env 키 값이 다른 파일에 복사됐는지, 브라우저 코드·네트워크 응답·서버 로그에 키가 있는지, 비밀 파일 주소 직접 접근 차단, 개인정보, 커밋 작성자 이메일
- 보완: 서버 오류의 자세한 내용은 서버 로그에만 남기고 브라우저엔 짧은 안내만 보냄 / 배포 제외 목록(.vercelignore) 추가 / 파이썬 캐시 무시 / 개발 서버에서 scripts 폴더 접근 차단
- 키 등록 방식: API 키는 사용자가 Vercel 화면에 직접 입력 (채팅·파일·명령어를 거치지 않게)

### 21. 보안 2차 점검 + 요청 제한
- 키 유출 흔적 검사: 프로젝트, 대화 기록, 작업 임시 파일, 명령 기록에서 키 값 검색 → .env 외 0건
- 요청 제한(서버): 사용자(IP)당 1분 8회·하루 60회, 서버 전체 1분 40회·하루 800회, 요청 크기 6MB 제한
  → 공개 주소에서 AI를 무제한 호출해 무료 사용량을 다 써버리는 것(데모 중단) 방지
- 커밋 전 자동 검사(pre-commit, 로컬 전용): noreply 이메일이 아니거나 .env·키 형태 값·.env의 실제 값이 들어가면 커밋 차단 → 가짜 키로 테스트해 차단 확인
- 테스트 중 git 내부에 남은 임시 객체를 삭제하고 다시 검사 (0건)
- 최종 확인: 테스트 중 생긴 임시 객체 2개(.env, 키 복사 테스트 파일)에는 실제 키가 들어 있었음 → 삭제 후 git 내부 전체(압축 해제 포함)를 다시 검사해 0건. 원격 연결·커밋이 없던 상태라 이 컴퓨터 밖으로 나간 적 없음
- 업로드 예정 19개 파일 최종 검사 통과 (검사기가 가짜 비밀값을 잡는지도 확인)
- 저장소는 우선 Private로 만들고 Vercel로 사이트만 공개하기로 함 (제출 전 Public 전환 필요)

- 사용자 질문 "아까 키 들어간 거 히스토리에 남아있으면 안 되지 않나?" → 그 임시 객체는 첫 커밋 전에 이미 삭제되어 커밋 기록에 들어간 적 없음. 업로드 직전 git 내부 전체를 다시 검사해 0건 확인
- Private 저장소로 업로드 후 GitHub 쪽에서도 확인: Private, 파일 19개, .env 없음, 작성자 이메일 noreply

### 23. Vercel CLI · Supabase CLI 설치
- Vercel CLI: Node.js LTS(winget 공식 패키지) 설치 후 npm으로 설치
- Supabase CLI: winget에 없어서 Supabase 공식 GitHub 릴리스에서 내려받음. 체크섬(SHA-256)이 공식 목록과 일치할 때만 설치하도록 함
  (처음엔 파일 이름 표기 차이로 불일치로 나와 설치를 멈추고 원인부터 확인 → 해시 자체는 일치)
- 로그인은 사용자가 브라우저에서 직접 (토큰이 채팅·저장소에 남지 않게)
- GitHub·Supabase·Vercel CLI 모두 사용자가 브라우저에서 직접 로그인 완료 (토큰은 채팅·저장소에 없음)
